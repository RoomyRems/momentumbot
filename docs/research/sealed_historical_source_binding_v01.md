# Original historical source binding v0.1

This isolated child starts from verified continuity checkpoint
`b10c8e675161c22658633d70e07960781c405cd3`, tree
`8ecd1bd27e2df355986a47e305109f5294f03413`. It pins 214 parent files.
The hypothesis is that original source binding can preserve causal candidate
identity, exact execution and management windows, and explicit carry gaps.
Ross actions, fills, recaps and transcripts remain prohibited runtime inputs.

## Source authentication

The reader requires five exact GitHub archives: the final v0.13 scanner source,
the verified entry result and consumption pair, the complete management bundle,
and the complete exit bundle. Each archive must match its independently verified
byte count and SHA-256 before its contents are opened. Input paths and archive
members reject symlinks, traversal and duplicate members. No provider access or
new capture is part of this component.

Every original first qualifying scanner activation is reconstructed from its
frozen snapshot. The reader selects its exact committed row; it never chooses a
later row or accepts a caller's rank hint. The unchanged general/small profiles
project that row into the candidate structure used by the account scheduler.
Micro plan, activation, profile membership and nanosecond decision timestamps
remain bound to the original decision commitment.

Entry availability is recomputed from the original native quote/status pair and
compared with the frozen classification. The 23 unavailable entries remain in
the catalog and in their account slots. More extensive common exit quotes
cannot rescue them. Available input is not an accepted order or confirmed fill.

The management reader preserves every raw minute/SIP lineage envelope within
each opportunity's original window. Complete stream commitments include original
artifact/request IDs and composed/source ordinals. Native order, duplicate
occurrences and source segmentation are preserved. Common exit pairs retain each
opportunity's individual conditional-exit bounds, even when the shared tape is
longer. Future quote rows are execution evidence, not strategy observations.

The bound artifact includes all 192 activations, 109 opportunities and 360 slots
across the original 12 account paths. Its context-access report binds all 744
opportunity references to their exact path, slot, candidate and source decision.
No historical account balance, accepted order, trade outcome or P&L is produced.

## Carry dependencies

All 348 preceding-session transitions remain explicit. Their position population
and preceding-close commitment are conditional on later verified account replay.
The current source registration supplies no corporate-action continuity source,
next-session 7:00 a.m. New York mark pair, or execution window beyond an expired
original opportunity. These are recorded as unavailable registered dependencies;
this is not a claim that every market-data vendor lacks the data.

Split/raw price-normalization factors do not authenticate changes to account
share units. Missing evidence never assumes unchanged shares, a flat account,
liquidation, an acknowledged order or a reset attempt counter. A later account
run must retain known shares, basis, cash, pending orders and attempt history,
and block continuation when the required source evidence is unresolved.

## Runtime boundary and verification

The existing continuity component's synthetic execution guards remain intact.
This child exposes original source access and a bound catalog; it does not
enable historical account execution, financial metrics or retrospective labels.
The next step is an isolated historical account activation using these bindings,
with unresolved carry preserved. New windows or retries require a separate
registration rather than an implicit extension here.

The registration and 35 synthetic component tests were completed before the
original source-binding run. The independent checker uses only the standard
library and previously frozen independent native-record checks. It checks archive
bytes, original scanner/Micro joins, candidate projection, every management
lineage stream, native entry/exit identities and all account contexts. It does
not independently simulate fills or certify corporate-action completeness.
