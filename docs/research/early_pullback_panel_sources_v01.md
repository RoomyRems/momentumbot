# Early-pullback panel sources v0.1 — new-date source mechanics

## Frozen question and scope

This additive child starts from `d6dc01cddaf681b62f82dc2a46aae6fa2a1bfaa5`, tree
`dfb901b810e68ac4b5e577684952fde00ce6cc75`. The mechanical question is whether a
new catalogue and independently pinned source archive can reproduce the frozen
scanner, causal normalization and original Micro triggers on the exact selected
dates without changing the parent policy.

The [first-two experiment](early_pullback_selection_v01.md), its March–May 2026
dates, primary comparison, all account alternatives and the previous losing
baseline are unchanged. This step does not test profitability. The intended
hybrid still requires discretionary/context integration; component results
neither settle its edge nor promise eventual profitability. No attached
transcript records or real new-panel market records were opened.

## New identities, not remapped old dates

The catalogue requires all 30 selected dates in their original order and exact
09:30–16:00 New York regular-session clocks. UTC representations are accepted
only when they identify the same instants; tests cross the March daylight-saving
change. Missing dates, replacements, reordered dates, early closes and naive
timestamps fail validation. This is tested calendar parsing, not a claim that
an independent provider calendar has already been captured.

There are 24 distinct path identities: both arms, two accounts, three horizons
and two execution scenarios. Each has 30 chronological slots, one initial seed
and an explicit preceding-session identity. Seed amounts remain $30,000/$2,000.
An unbound source date has unknown opportunity state, not an inferred zero.

These are new source-catalogue objects. They are not submitted to the original
historical account engine under old session IDs. Its dated seed, candidate and
entry-context validators remain untouched. A separate engine-context adapter
is still required before these new slots can execute accounts. No cash, fills
or financial account results are generated by this component.

## Archive-to-feature reconstruction

The synthetic capture format has exactly 32 ZIP members: `manifest.json`,
`calendar.json`, and one `dates/YYYY-MM-DD.json` for each selected date. The
independent caller supplies the outer ZIP byte count/hash and the manifest's
full-envelope hash. Before deserializing a day, the reader checks the complete
member population, every uncompressed length and every member hash. Unsafe
paths, symlinks, duplicate members/JSON keys, extra files and missing dates are
rejected. The committed manifest is rechecked when members are read.

Each day contains the declared membership and candidate collections; split
previous closes and rank bars; raw candidate bars and exact RVOL; structured
float/news inputs; and the activated symbols' SIP trades, raw session minutes
and split-adjusted warmup. No caller-supplied scanner result, selected winner,
Micro plan or outcome is used as a substitute for reconstruction.

The original scanner v0.3 and frozen profile union rebuild candidate-minute
features. The unchanged general/small profile eligibility functions identify
each first qualifying activation, including exact-time profile unions. New
activation IDs bind the causal row and child catalogue, not an old experiment's
identity. Tests compare grouping with the original profile-activation helper.

Raw/split normalization uses the original median-ratio method on completed bars
before the earliest symbol activation. The raw scanner's preactivation close
and volume must agree with the independently supplied raw session-minute
support. Warmup is normalized using that evidence; no caller-supplied factor
is trusted. The original Micro builder then reconstructs all triggers.

Each trigger is also checked by the prior paired adapter against its original
plan, complete Micro-prefix hash, ordinal and first trigger. Its source envelope
contains only completed support, prior warmup and SIP records through that
trigger. Tied receive order is retained. Future news and later trades cannot
change an earlier activation or causal prefix in the synthetic tests.

Both arms receive the same complete reconstructed source union; the first-two
gate is not applied while collecting opportunities. Missing activated-symbol
sources fail rather than becoming a no-trigger result. An explicitly empty
synthetic trade tape and a declared no-candidate synthetic date remain distinct.
Neither establishes a historical zero-opportunity day without provider-source
completeness. Every bound slot still says execution inputs are not acquired.

## Verification is deliberately limited

| Layer | Verified here | Still required for historical use |
|---|---|---|
| Calendar | Exact selected-date and session-clock validation, including DST | Independently captured provider calendar |
| Capture | External ZIP/manifest commitments and every member's bytes | Vendor origin, exact request/response lineage and exhaustion receipts |
| Scanner | Frozen feature and first-qualification reconstruction over the committed inputs | Point-in-time membership/identity, candidate-discovery completeness and SEC/news provenance |
| Micro | Causal raw/split factor, support bridge, complete original trigger/prefix reproduction | Real complete SIP/minute/warmup captures with trusted request bounds |
| Account paths | New identities, fixed seeds and 720 source slots shared across arms | New-catalogue engine-context integration, execution/management sources and historical activation |

Matching a producer's self-supplied hash does not make that producer independent.
The expected archive and manifest commitments must ultimately come from a
separately verified capture record. This version accepts only explicitly
synthetic fixtures and symbols; a caller cannot turn it into historical or
brokerage execution by changing a mode field. Publication creates no provider
transport, provider availability claim or data-acquisition authority.

## Reproducible evidence

Registration: `5743bf8ab6a70f2c78d61f98ef841a054bc804076fd0d0d4ae0b7c1c2145b87e`.
It binds 322 files, including the immutable paired-account ancestry and the
scanner/Micro helpers used by this child.

The [frozen synthetic bundle verification](../../research/data-audits/early-pullback-panel-sources-v0.1/synthetic-bundle-verification.json)
records its exact archive and manifest pins, all 30 dates and 720 slots, and two
identical reconstructions. It is a reproducibility check, not an independent
second source engine. To verify the saved synthetic archive from the repo root:

```python
import json
from pathlib import Path
from momentumbot.research import early_pullback_panel_sources_v01 as source

base = Path(source.BASE)
audit = json.loads((base / "synthetic-bundle-verification.json").read_bytes())
with source.SourceArchive(base / audit["archive_file"],
        expected_archive=audit["archive_commitment"],
        expected_manifest_sha256=audit["manifest_sha256"]) as archive:
    result = source.bind_panel(archive)
source.require(source.fingerprint(result) == audit["result_full_envelope_sha256"],
               "frozen synthetic source reconstruction differs")
```
